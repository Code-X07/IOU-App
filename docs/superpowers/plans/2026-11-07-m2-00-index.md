## Locked decisions (apply to every part)

1. **The friend's UI code (`ui/`) stays theirs.** The `api` changes keep it compiling without touching their screens:
   - `ExpenseDraft` gets `payers: List<SplitInput>` and `payerSplit: PayerSplit` in its primary constructor and keeps a **secondary constructor with the old parameter order** (`payer: PersonId` first), which makes one `EQUAL` payer. `ExpenseDraft.payer` stays as a `@Deprecated` read accessor (the first payer).
   - `ActivityItem` keeps `paidBy` (first payer of an expense, sender of a transfer) and gains `payers: List<PayerView>`.
   - The only `ui/` file the plan edits is `ui/forms/LedgerErrorMessage.kt`: its `when` over `LedgerError` is exhaustive, so each new error gets one message line in the task that adds the error (owner's decision, 2026-11-07). New screens (payers, schedules, the due list, the notification permission) are the friend's work, listed in `docs/m2-ui-contract-changes.md`.
2. **`PayerSplit`** is its own enum in `ledger.model` (`EQUAL`, `EXACT`), with `splitType` mapping it onto `SplitType` for `SplitResolver`.
3. **One Room schema 2 and one hand-written `Migration(1, 2)`**, grown across parts: Part 1 adds `expense_payer` and rebuilds `expense` without `payerPersonId`; Part 4 adds `recurringId` / `recurringOn` to that rebuild and creates `recurring_expense` and `recurring_participant`. Nothing is released between parts, so changing an unreleased migration is fine. `app/schemas/.../2.json` is regenerated by the build each time.
4. **Migration tests run on the plain JVM without `room-testing`.** `MigrationTestHelper` needs instrumentation in an Android module, so `MigrationTest` builds a version-1 database itself from `app/schemas/io.github.codex07.iou.data.IouDatabase/1.json` (its `createSql` and `setupQueries`, `PRAGMA user_version = 1`) with the bundled driver, then opens it with `IouDatabase` and the migration. Room validates the migrated schema against version 2 when it opens.
5. **Snapshot schema 2** (`SnapshotCodec.CURRENT_SCHEMA = 2`) has one upcaster, 1 → 2, also grown across parts: payers in Part 1, `recurringId` / `recurringOn` in Part 4. Stored snapshots are never rewritten.
6. **`WriteContext.today`** (Part 3) is the store's local date (`LedgerStore.today()`, device zone). Ops that need dates (cut-off rule, due checks) read it from the context, never from a clock.
7. **The cut-off rule and hold resumes live in one place:** `RecurringOps.finalize(ctx, plan)` (Part 3) runs on every `WritePlan` the store commits, after the op built it and before validation of the final plan, so no write path can skip it (spec §5.7 "The cut-off rule", "Every hold end is a write").
8. **Fake and real share the runner.** `RecurringRunner` lives in `store` and runs in both flavors in the foreground; only the real flavor adds the WorkManager worker and Android notifications (spec §6.3).
9. **Full check** at the end of each part (from `android/`, `JAVA_HOME` = MS JDK 21, see `state.md`): `.\gradlew.bat testFakeDebugUnitTest testRealDebugUnitTest`, then `.\gradlew.bat assembleFakeDebug assembleRealDebug assembleRealRelease`, then `.\gradlew.bat lintFakeDebug lintRealDebug`. Count results from the XML reports.
10. **Git:** commit after every task with a plain message, no attribution; only `android/`, `docs/` (and `.github/`, `README.md`) are tracked. Push as the owner directs.
11. **M0 and M1 plan files are frozen history.** M2's changes to their code are documented here and in the parts only.
12. **Docs move with the code:** the task that changes behaviour updates the spec if the code deviates, `docs/ui-contributor-guide.md` for `api` changes, and `docs/m2-ui-contract-changes.md` if the friend's summary changes.
