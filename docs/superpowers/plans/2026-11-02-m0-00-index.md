# Milestone 0 Implementation Plan: Index

> **For agentic workers:** this file is the map. Each part below is its own plan with its own header; execute them in the order given with superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Read this index first: its **Locked decisions** and **Type inventory** apply to every part.

**Goal:** Milestone 0 of the MVP spec (`docs/superpowers/specs/2026-11-02-iou-mvp-design.md` §12): the friend (UI contributor) can build real screens against a stable `api` and an in-memory fake that behaves like the real thing.

**M0 acceptance criteria (spec §12, verbatim):**

1. `fakeDebug` builds and runs; every `*Api` returns seeded data, and writes update all observers.
2. The fake rejects invalid writes with the same `LedgerError`s the spec defines (e.g. a 3-person ad-hoc expense → `NeedsGroup`).
3. CI is green on push; a `v0.0.1` tag produces a signed APK on a GitHub Release.
4. The `api` package has no Android imports and no `Double`/`Float` in money paths (CI-checked).

Part 3 comes before the engine on purpose: it only needs the model and the errors, and it unblocks the friend earliest.

Why `ops` and `views` are separate packages: the write rules (draft → rows, FX, cascades, merges) and the read projections are the same for the fake and the real implementation. Keeping them pure and outside `fake` means M1's `LedgerWriter` and real `*Api`s reuse them, and the fake stays a thin in-memory store. This also makes "the fake behaves like the real thing" (ADR-0004) true by construction.

## Locked decisions (apply to every part)

1. **Paths.** Gradle root `android/`, single module `:app`. Kotlin sources under `android/app/src/<sourceSet>/kotlin/io/github/codex07/iou/`. Source sets: `main` (everything shared, including `money`, `ledger.*`, `api`, `fake`), `fake` and `real` (flavor-specific Hilt modules only), `test` (JVM unit tests, contract suites). No instrumentation tests in M0.
2. **Package dependency direction** (enforced by review, not the compiler): `money` ← `ledger.model` ← `api` ← `ledger.engine` ← `ledger.rules` ← `ledger.ops` ← `ledger.views` ← `fake` ← flavor `di` modules ← `ui`. `api` imports only `money` and `ledger.model`. `LedgerError` and `LedgerResult` live in `api` (spec §6.2) and the `ledger.*` packages below it import them; `api` never imports `ledger.engine`, `ledger.rules`, `ledger.ops`, `ledger.views` or `fake`. `ui` imports only `api`, `money` and `ledger.model`.
3. **Android-free packages** (`money`, `ledger` and all its subpackages, `api`, `fake`) may use the JVM standard library: `java.time` (`Instant`, `LocalDate`), `java.math.BigDecimal`/`BigInteger`, `java.util.Currency`, `java.util.UUID`. No `android.*`, `androidx.*`. `Double`/`Float` never appear in `money`, `ledger`, `api`, `data`, `io` (spec §11). Both rules are checked by `DomainPurityTest` (Part 1), which CI runs. The device runs Android's library, not the JDK's: with minSdk 30, use only JDK methods Android has at API 30 or that D8 in the pinned AGP backports. JVM tests can't catch this; lint's `NewApi` check (`lintFakeDebug` in CI) does. Known trap: `BigInteger.longValueExact()`/`intValueExact()` need API 31, so bound-check and use `toLong()`; `BigDecimal.longValueExact()` is fine.
4. **Money in the domain** is `money.Money(amountMinor: Long, currency: CurrencyCode)`. Long arithmetic on money uses `Math.addExact`/`subtractExact`/`multiplyExact`/`negateExact`; an overflow throws `ArithmeticException`, which the write path (fake now, `LedgerWriter` in M1) turns into `LedgerError.AmountTooLarge`.
5. **IDs** are `@JvmInline value class`es over UUID strings (one type per entity kind, see the inventory). Transfers and expenses share `EntryId`.
6. **Time** comes from an injected `java.time.Clock`; new IDs from an injected `IdGenerator` (Part 2). Tests use fixed clocks and sequential IDs, never `Instant.now()` or `UUID.randomUUID()` directly.
7. **Tests:** JUnit 5 (Jupiter) + Kotest assertions + Kotest property testing (`checkAll` inside JUnit tests; no Kotest runner), `kotlinx-coroutines-test` and Turbine for `Flow`s. Contract suites are abstract classes in `src/test`; Part 6 adds `Fake*ContractTest` subclasses, M1 adds `Real*ContractTest` subclasses.
8. **The `real` flavor in M0** binds the same in-memory implementation as `fake`, but with an empty ledger (no seed data). M1 replaces that binding with Room. The `fake` flavor is the one the friend uses.
9. **Versions** are pinned to a set known to work together (Part 1, `libs.versions.toml`): Gradle 8.14.3, AGP 8.13.0, Kotlin 2.2.20, KSP 2.2.20-2.0.3, Hilt 2.57.1, Compose BOM 2025.09.00. Moving to AGP 9 / Kotlin 2.3 is a separate chore after M0; don't mix it into M0 tasks.
10. **Git:** commit after every task; push straight to `main` (the repo's working mode); plain commit messages, **no attribution lines**. Only `android/`, `docs/`, `.github/`, `README.md` are tracked (root `CLAUDE.md`).
11. **Release signing secrets** (`RELEASE_KEYSTORE_BASE64`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD`) are created and stored by the project owner by hand (Part 1, Task 7). Agents never handle the passwords. The `v0.0.1` tag is pushed at the end of Part 7.
12. **API change process** (spec §6.4): after Part 3 lands, any change to `api` is a small PR touching `api` and the fake together, reviewed by both contributors. Part 3 writes this into `docs/ui-contributor-guide.md`.

## Type inventory (names shared across parts)

Parts must use these exact names. A part may add members or types; renaming or removing anything listed here requires updating this index in the same commit.

**`money`** (Part 1)
- `CurrencyCode(code: String)`: value class; constructor rejects codes `java.util.Currency` doesn't know or that have no minor-unit digits. `fractionDigits: Int`; `CurrencyCode.parse(text): CurrencyCode?`.
- `Money(amountMinor: Long, currency: CurrencyCode)`: `plus`, `minus`, `unaryMinus` (exact; mismatched currencies throw `IllegalArgumentException`), `toPlainString()` ("12.34"), `toString()` ("12.34 EUR"), `Money.zero(currency)`.
- `MAX_MINOR: Long = 10_000_000_000_000`.
- `MoneyParser.parse(text, currency): MoneyParseResult` (`Ok(money)` / `Err(MoneyError)`); `MoneyError` = `InvalidAmount`, `TooManyDecimals(maxDecimals)`, `AmountTooLarge`.

**`ledger.model`** (Part 2)
- IDs: `PersonId`, `GroupId`, `MembershipId`, `HandleId`, `EntryId`, `FxSnapshotId`, `ImportBatchId`, `RevisionId`, `DeviceId`, `LedgerGeneration`, each `(value: String)`.
- `IdGenerator` (fun interface `next(): String`), `SyncMeta(createdAt, updatedAt, authorId: PersonId, deletedAt: Instant?, version: Int, importBatchId: ImportBatchId?)`.
- `sealed interface LedgerEntity` implemented by `Person`, `PaymentHandle`, `Group`, `GroupMember`, `Transfer`, `Expense`; `sealed interface Entry : LedgerEntity` implemented by `Transfer`, `Expense`.
- `ExpenseShare(personId, shareMinor: Long, inputValue: Long?)`, `FxSnapshot`, `EntryRevision` (its `snapshot` is the entity itself; JSON is M1's concern), `ImportBatch`.
- `Change(entity: LedgerEntity, action: RevisionAction, reason: String?)`: one row a write touches; one revision each.
- `FieldChange(field, before: String?, after: String?)`, `SplitInput(personId, value: Long?)`: plain data shared by engine, ops and api.
- Enums: `HandleType`, `FxMode`, `TransferKind`, `TransferMethod`, `Category`, `SplitType`, `FxSource`, `EntityType`, `RevisionAction`, `ImportSource`.
- `LedgerState`: immutable maps of every entity table keyed by ID, plus `me`, `meOrNull`, `entries`, `entry(id)`, `entity(type, id)`, `with(...)`, `applying(changes, snapshots)`.
- Test fixture (in `src/test`): `testutil.TestLedger`, `SequentialIds`, `testMeta`, constants `EUR`, `SEK`, `USD`, `JPY`, `BHD`, `IDR`, `T0`, `D0`, `ME`, helpers `eur()`, `sek()`, `usd()`.

**`api`** (errors in Part 2, the rest in Part 3)
- `sealed interface LedgerResult<out T>`: `Ok(value)`, `Err(error)`; `map`, `flatMap`, `getOrNull`, `errorOrNull`; builder `ledgerResult { … bind() … fail(e) … ensure(c) { e } }`.
- `sealed interface LedgerError`: every error of spec §4.4 and §8, plus `NotFound`, `InvalidField`, `RateRequired`, `MissingInput`, `WeightOutOfRange`, `DuplicateParticipant` and M1's file errors; `MergeProblem`; `RuleViolation(rule: Int, error: LedgerError)` for `RestoreConflict` (rule 0 = field validity).
- Interfaces: `SetupApi`, `PeopleApi`, `GroupsApi`, `LedgerApi`, `FxApi`, `BackupApi`, `ImportExportApi`, `SettingsApi`.
- `EditToken(generation: LedgerGeneration, version: Int)`; every non-token write input has `basis: LedgerGeneration`; `DocumentRef(uri: String)`.
- `PersonDetail.aliases: List<AliasView(person, mergedInto, token)>`: each alias row's own token, used by `unmerge` (ADR-0009).
- `RevisionView(entity: EntityRef, subject, version, …)`. `PersonDetail.history` holds the revisions of the person's records (aliases included) and their handles; `GroupDetail.history` those of the group and its memberships; deleted rows included, so every revision is reachable (spec §1).

**`ledger.engine`** (Parts 2 and 4)
- `IdentityResolver(state)`: `canonical(PersonId)`, `brokenChains`, `recordsOf(canonical)`, `handlesOf(canonical)`, `defaultHandle(canonical, type)`, `memberships(groupId, canonical)`, `hasMembership(groupId, canonical)`, `isActiveMember(groupId, canonical)`, `canonicalMembers(groupId)`.
- `SplitResolver.resolve(type, effectTotalMinor, originalTotalMinor, inputs: List<SplitInput>): LedgerResult<List<ExpenseShare>>`, `largestRemainder(total, weights)`.
- `FxConverter`: `validateRate`, `convert(amount, to, rate)`, `deriveRate(paid, charged)`, `invert(rate)`, `cross(homeToBase, homeToQuote)`.
- `Effect(creditor, debtor, amount: Money, groupId: GroupId?)`, `LedgerEngine.compute(state): Balances`.
- `SettlePlanner`, `PlannedTransfer(from, to, amount: Money)`.
- `RevisionDiff.diff(before: LedgerEntity?, after: LedgerEntity, names): List<FieldChange>`, `DiffNames`, `DiffField`. Fields are paired and compared by ID, shown by name.

**`ledger.rules`** (Part 5)
- `LedgerValidator.validate(before: LedgerState, after: LedgerState, op: WriteOp): List<RuleViolation>`; `WriteOp` hierarchy and `FieldRules` (IBAN, Revtag, phone) defined in Part 5.

**`ledger.ops`** (Part 6)
- `WriteContext(state, generation, now, ids, meId)`, `WritePlan(changes: List<Change>, snapshots: List<FxSnapshot>)`, `object LedgerOps` with one function per write; every function returns `LedgerResult<WritePlan>` (or a plan plus the new ID).

**`ledger.views`** (Part 7)
- `LedgerViews(state, revisions, generation, homeCurrency, rates)`: builds every `api` read model; settle-up drafts; merge and split previews.

**`fake`** (Part 7)
- `InMemoryLedger` (state, revisions, generation, `ledgerSeq`, settings, `StateFlow`; applies `WritePlan`s), one `Fake*Api` class per interface, `SeedData`.
