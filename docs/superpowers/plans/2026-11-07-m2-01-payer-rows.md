# M2 Part 1: Payer Rows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Read `docs/superpowers/plans/2026-11-07-m2-00-index.md` first: its locked decisions and type inventory apply here.

**Goal:** Every expense stores its payers as `ExpensePayer` rows with a `payerSplit`, in memory, in Room (schema 2), in revision snapshots (schema 2), in backups and in normalized exports, and balances come from contributions. Data written by `v0.1.0` (Room schema 1, schema-1 snapshots, version-1 backups, schema-1 exports) becomes one `EQUAL` payer paying the effect total, so no balance moves. Through the `api` an expense still has exactly one payer; Part 2 opens it up.

**Architecture:** `payerPersonId` disappears from `Expense`. `LedgerEngine` turns payer and share rows into per-person contributions and matches creditors with debtors (spec §4.2). `SplitResolver.resolvePayers` resolves payer inputs like shares. The validator checks stored payer rows (rule 0) and resolves them through `personIds` for rules 1, 3, 10 and 15. Persistence follows the share pattern: an owned `expense_payer` table, payer rows inside the expense snapshot, a `payers` list in `LedgerRows`, and an `expense_payers.csv` table. Old formats are upgraded at their boundary by one shared JSON helper (`Migrations.expense1To2`) and by the Room migration.

**Tech Stack:** Kotlin, Room 2.8.1 on the driver API (bundled SQLite in JVM tests), kotlinx.serialization, Commons CSV, JUnit 5, Kotest.

## Global Constraints

- **Payers (spec §3.2, §4.4):** at least one payer row per expense; distinct person IDs; `paidMinor` ≥ 0 in the effect currency; Σ `paidMinor` = `effectTotalMinor`; `EQUAL` rows carry no input; `EXACT` inputs are amounts in the paid currency, each > 0, summing to `totalMinor`. Errors `NoPayers`, `PaidRemaining(diffMinor)`, `DuplicatePayer(personId)`, `InvalidAmount` (an EXACT payer who paid 0), `NegativeInput`, `MissingInput`, `AmountTooLarge`. Through import these appear as `CorruptData` or the same errors on invalid rows.
- **Effects (spec §4.2, ADR-0012):** contribution `c(X) = Σ paid(X) − Σ share(X)` per canonical person; repeatedly match the largest remaining creditor with the largest remaining debtor (ties to the lowest person UUID, string order); `Effect(creditor, debtor, effectCurrency, min(credit, |debt|), groupId)`. Exact `Long` arithmetic (`Math.addExact` / `subtractExact`). One payer gives exactly the pre-M2 effects.
- **Schema-1 mapping (spec §3.2, §5.5, §7.1, §7.4):** `payerPersonId` → one payer row (that person, `paidMinor` = effect total, no input, position 0), `payerSplit = EQUAL`. Same result from `Migration(1, 2)`, the snapshot upcaster, a version-1 backup and a schema-1 export.
- **Normalized shape (spec §7.2):** schema 2 tables in order `people, payment_handles, groups, group_members, fx_snapshots, transfers, expenses, expense_shares, expense_payers` (Part 4 adds the two recurring tables before `expenses`). `expenses` has `payer_split` instead of `payer_person_id`. `expense_payers` has `expense_id, position, person_id, paid_minor, paid, input_value`; `paid` is in the expense's effect currency. A schema-1 file has exactly the schema-1 tables.
- **Report (spec §7.2):** `paid_by` is the payer's canonical name; with several payers each name with its amount in the paid currency, `Alice 60.00; Bob 40.00`.
- No `ui/` file except `ui/forms/LedgerErrorMessage.kt` (index, locked decision 1).

```kotlin
    /**
     * Spec §4.2 (ADR-0012): each canonical person's contribution is what they paid minus their share. Creditors
     * (contribution > 0) and debtors (< 0) are matched like a settle plan without the amount cap: the largest
     * remaining creditor with the largest remaining debtor, ties to the lowest person ID. Exact arithmetic, so
     * each person's effects add up to their contribution. With one payer this gives `Effect(payer, X, share(X))`
     * for every other person with a share, as before multiple payers.
     */
    private fun expenseEffects(expense: Expense, resolver: IdentityResolver): List<Effect> {
        val contributions = LinkedHashMap<PersonId, Long>()
        for (payer in expense.payers) {
            val person = resolver.canonical(payer.personId)
            contributions[person] = Math.addExact(contributions[person] ?: 0L, payer.paidMinor)
        }
        for (share in expense.shares) {
            val person = resolver.canonical(share.personId)
            contributions[person] = Math.subtractExact(contributions[person] ?: 0L, share.shareMinor)
        }
        val credit = contributions.filterValues { it > 0 }.toMutableMap()
        val debt = contributions.filterValues { it < 0 }.mapValues { -it.value }.toMutableMap()
        val largest = compareByDescending<Map.Entry<PersonId, Long>> { it.value }.thenBy { it.key.value }
        val effects = mutableListOf<Effect>()
        while (credit.isNotEmpty() && debt.isNotEmpty()) {
            val (creditor, available) = credit.entries.sortedWith(largest).first().toPair()
            val (debtor, owed) = debt.entries.sortedWith(largest).first().toPair()
            val amount = minOf(available, owed)
            effects += Effect(creditor, debtor, Money(amount, expense.effectTotal.currency), expense.groupId)
            if (available == amount) credit.remove(creditor) else credit[creditor] = available - amount
            if (owed == amount) debt.remove(debtor) else debt[debtor] = owed - amount
        }
        return effects
    }
```

Contributions sum to 0 (Σ paid = Σ shares = effect total, rule 0), so the loop ends with both maps empty. The order of a single-payer expense's effects changes from share order to largest debtor first; balances and flows are sums, so nothing else changes.

```kotlin
     * `MissingInput`, `AmountTooLarge` as for shares.
     */
    fun resolvePayers(
        split: PayerSplit,
        effectTotalMinor: Long,
        originalTotalMinor: Long,
        inputs: List<SplitInput>,
    ): LedgerResult<List<ExpensePayer>> = ledgerResult {
        ensure(inputs.isNotEmpty()) { LedgerError.NoPayers }
        inputs.groupBy { it.personId }.entries.firstOrNull { it.value.size > 1 }
            ?.let { fail(LedgerError.DuplicatePayer(it.key)) }
        if (split == PayerSplit.EXACT) {
            inputs.firstOrNull { (it.value ?: 0L) < 0L }?.let { fail(LedgerError.NegativeInput(it.personId)) }
            inputs.firstOrNull { it.value == null }?.let { fail(LedgerError.MissingInput(it.personId)) }
            ensure(inputs.none { it.value == 0L }) { LedgerError.InvalidAmount }
        }
        val resolved = when (val result = resolve(split.splitType, effectTotalMinor, originalTotalMinor, inputs)) {
            is LedgerResult.Ok -> result.value
            is LedgerResult.Err -> {
                val error = result.error
                fail(if (error is LedgerError.ExactRemaining) LedgerError.PaidRemaining(error.diffMinor) else error)
            }
        }
        resolved.map { ExpensePayer(it.personId, it.shareMinor, it.inputValue) }
    }
```

```kotlin
/**
 * Schema changes of the ledger database and of the formats that share its row shape (spec §3.2, §5.5, §7.1).
 * Schema 1 is `v0.1.0`; schema 2 is M2. Every expense of schema 1 had exactly one payer, `payerPersonId`, which
 * becomes one payer row paying the effect total with `payerSplit = EQUAL`, so no balance changes (§4.2).

object Migrations {

    /** Room schema 1 → 2 (spec §3.2), written by hand. One migration for all of M2 (index, locked decision 3). */
    val MIGRATION_1_2 = object : Migration(1, 2) {
        override fun migrate(connection: SQLiteConnection) {
            connection.execSQL(
                "CREATE TABLE IF NOT EXISTS `expense_payer` (`expenseId` TEXT NOT NULL, `personId` TEXT NOT NULL, " +
                    "`position` INTEGER NOT NULL, `paidMinor` INTEGER NOT NULL, `inputValue` INTEGER, " +
                    "PRIMARY KEY(`expenseId`, `personId`))",
            )
            connection.execSQL(
                "INSERT INTO `expense_payer` (`expenseId`, `personId`, `position`, `paidMinor`, `inputValue`) " +
                    "SELECT `id`, `payerPersonId`, 0, `effectTotalMinor`, NULL FROM `expense`",
            )
            connection.execSQL(
                "CREATE TABLE `expense_new` (`id` TEXT NOT NULL, `groupId` TEXT, `payerSplit` TEXT NOT NULL, " +
                    "`description` TEXT NOT NULL, `category` TEXT, `totalMinor` INTEGER NOT NULL, `currency` TEXT NOT NULL, " +
                    "`effectTotalMinor` INTEGER NOT NULL, `effectCurrency` TEXT NOT NULL, `fxSnapshotId` TEXT, " +
                    "`splitType` TEXT NOT NULL, `occurredOn` TEXT NOT NULL, `note` TEXT, `createdAt` TEXT NOT NULL, " +
                    "`updatedAt` TEXT NOT NULL, `authorId` TEXT NOT NULL, `deletedAt` TEXT, `version` INTEGER NOT NULL, " +
                    "`importBatchId` TEXT, PRIMARY KEY(`id`))",
            )
            connection.execSQL(
                "INSERT INTO `expense_new` (`id`, `groupId`, `payerSplit`, `description`, `category`, `totalMinor`, `currency`, " +
                    "`effectTotalMinor`, `effectCurrency`, `fxSnapshotId`, `splitType`, `occurredOn`, `note`, `createdAt`, " +
                    "`updatedAt`, `authorId`, `deletedAt`, `version`, `importBatchId`) " +
                    "SELECT `id`, `groupId`, 'EQUAL', `description`, `category`, `totalMinor`, `currency`, `effectTotalMinor`, " +
                    "`effectCurrency`, `fxSnapshotId`, `splitType`, `occurredOn`, `note`, `createdAt`, `updatedAt`, `authorId`, " +
                    "`deletedAt`, `version`, `importBatchId` FROM `expense`",
            )
            connection.execSQL("DROP TABLE `expense`")
            connection.execSQL("ALTER TABLE `expense_new` RENAME TO `expense`")
        }
    }

    val ALL: Array<Migration> = arrayOf(MIGRATION_1_2)

    /**
     * A schema-1 expense row as JSON → the schema-2 row and its one payer row. Shared by the snapshot upcaster and
     * the version-1 backup reader, so both give exactly what [MIGRATION_1_2] gives.
     */
    fun expense1To2(expense: JsonObject): Pair<JsonObject, JsonObject> {
        val payer = buildJsonObject {
            put("expenseId", expense.getValue("id"))
            put("personId", expense.getValue("payerPersonId"))
            put("position", JsonPrimitive(0))
            put("paidMinor", expense.getValue("effectTotalMinor"))
            put("inputValue", JsonNull)
        }
        return JsonObject(expense - "payerPersonId" + ("payerSplit" to JsonPrimitive("EQUAL"))) to payer
    }

    /** The `rows` object of a version-1 backup → version 2: expense rows upgraded, their payer rows added. */
    fun backupRows1To2(rows: JsonObject): JsonObject {
        val upgraded = rows["expenses"]?.jsonArray.orEmpty().map { expense1To2(it.jsonObject) }
        return JsonObject(
            rows + mapOf(
                "expenses" to JsonArray(upgraded.map { it.first }),
                "payers" to JsonArray(upgraded.map { it.second }),
            ),
        )
    }
}
```

```kotlin
     * `paid_by` (spec §7.2): the payer's name, or each payer's name with what they paid in the paid currency:

        if (expense.payers.size == 1) return name(expense.payers.single().personId)
```
